# 클라우드 작업 지시: 사이트 만들기

`docs/기획서.md`가 기준이다. 페이지, 원칙, 디자인, 기술은 모두 기획서를 따른다. 먼저 읽고 시작한다.

1. Astro 정적 사이트와 `data/` 아래 JSON 데이터로 만든다. 화면 글은 모두 한국어로 쓰고, 글꼴은 Pretendard를 쓴다. 밝은 모드와 어두운 모드를 지원하고 폰 화면을 먼저 만든다. 디자인은 깔끔하면서 요즘 스타일로 한다: 벤토 그리드, 반투명 메뉴, 페이지 전환 효과, 마우스를 올리면 살짝 떠오르는 카드, 노란 강조. 멤버 색은 포인트로만 쓴다(토미 노랑, 슈이 보라, 메이 분홍, 카니 빨강, 소하 주황, 도희 하양, 준휘 검정→밝은 회색, 승주 초록).
2. 기획서의 페이지 10개를 모두 만든다. 방문자용 **운영 원칙** 페이지도 포함한다. 모든 페이지 맨 아래에 "비공식 팬 사이트 · 운영 원칙 · 삭제 요청(rhfo4333@gmail.com)"을 둔다.
3. 압축본 검색은 챕터(장면) 이름까지 찾는다. 챕터를 누르면 유튜브 영상이 그 시간부터 재생된다.
4. 데이터
   - 실제 에피소드 데이터는 사용자 PC에 있어서 여기서는 쓸 수 없다. 스키마와 샘플 2~3개(`"sample": true`)만 만들고, 샘플에는 "샘플" 표시를 붙인다. 스키마 설명은 `data/README.md`에 쓴다.
   - 세이마이네임 정보(멤버 8명 토미·슈이·메이·카니·소하·도희·준휘·승주, 생일, 데뷔, 디스코그래피)는 공식 공개 출처에서 확인하고, 항목마다 `source` URL을 단다. 확인하지 못한 건 넣지 말고 PR에 따로 적는다.
   - 가사, 사생활, 루머, 공식 사진·영상 재업로드는 넣지 않는다. 영상은 유튜브 퍼가기와 링크만 쓴다.
5. GitHub Pages(`/romi-im` 경로)에 자동으로 올리는 GitHub Actions를 만든다.
6. `npm run build`로 오류가 없게 하고, 폰 너비 화면을 확인한다.
7. 새 브랜치에 커밋하고 PR 하나를 연다. PR 설명은 비개발자가 읽기 쉬운 한국어로 쓴다: 페이지별 내용, 가능하면 스크린샷, 채워야 할 데이터, 주인이 직접 해야 할 일(Settings → Pages → Source: GitHub Actions).

완료 기준: 빌드가 되고 기획서와 맞는 사이트가 PR로 올라와 있다.
