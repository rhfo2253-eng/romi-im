## 2. 파일 고치는 기본 방법 (모든 작업 공통)

1. https://github.com/rhfo2253-eng/romi-im 에 로그인한 상태로 들어갑니다.
2. `data` 폴더 → 고칠 파일(예: `events.json`)을 누릅니다.
3. 오른쪽 위 **연필 아이콘(Edit this file)** 을 누릅니다.
4. 내용을 고칩니다. (아래 예시를 복사해서 값만 바꾸면 됩니다.)
5. 오른쪽 위 초록 버튼 **Commit changes...** → 창에서 다시 **Commit changes** 를 누릅니다.
   - "Commit directly to the `main` branch"가 선택된 상태 그대로 두면 됩니다.
6. 1~3분 뒤 사이트에 반영됩니다. 반영됐는지는 5번(확인하는 법)을 보세요.

### 꼭 지킬 형식 (틀리면 사이트가 안 바뀜)

- 글자는 **큰따옴표** `"` 로 감쌉니다. 작은따옴표 `'` 는 안 됩니다.
- 항목과 항목 사이에는 **쉼표** `,` 를 넣습니다. **마지막 항목 뒤에는 쉼표를 넣지 않습니다.**
- 날짜는 `"2026-11-16"` 형식(연-월-일, 두 자리씩)입니다.
- 멤버 이름은 영어 id로 적습니다:

  | 멤버 | id |
  |---|---|
  | 히토미 | `hitomi` |
  | 슈이 | `shuie` |
  | 메이 | `mei` |
  | 카니 | `kanny` |
  | 소하 | `soha` |
  | 도희 | `dohee` |
  | 준휘 | `junhwi` |
  | 승주 | `seungju` |

- 형식이 틀리면 사이트는 **이전 상태 그대로** 유지됩니다(망가지지 않음). 5번을 보고 고치면 됩니다.

## 3. 자주 하는 작업 (복사해서 쓰는 예시)

### 3-1. 출연·공연 일정 추가 → `data/events.json`

파일 맨 끝 `]` 바로 위, 마지막 `}` 뒤에 쉼표를 찍고 아래를 붙여 넣습니다.

```json
  {
    "id": "2026-11-20-radio",
    "date": "2026-11-20",
    "type": "broadcast",
    "title": "KBS 쿨FM '프로그램 이름' 출연 (오후 8시)",
    "source": "https://x.com/sa2m2nam3/status/게시물번호"
  }
```

- `id`: 겹치지 않는 아무 이름. `날짜-짧은영어` 로 쓰면 편합니다.
- `type`: 방송·유튜브 출연은 `"broadcast"`, 공연·행사·시구·팬사인회는 `"event"`.
- `source`: 공식 X 게시물이나 기사 주소. **출처 없는 일정은 넣지 않습니다**(운영 원칙).
- 달력과 홈 "다가오는 날"에 자동으로 나옵니다.

**공식 X 게시물 주소 얻는 법**: X 앱에서 게시물 → 공유 → 링크 복사.

### 3-2. 사진(공식 게시물) 추가 → `data/photos.json`

```json
  {
    "url": "https://x.com/sa2m2nam3/status/게시물번호",
    "platform": "x",
    "date": "2026-11-01",
    "members": ["mei", "dohee"]
  }
```

- `platform`: X는 `"x"`, 인스타그램은 `"instagram"`, 위버스는 `"weverse"`.
- 인스타그램 주소 예: `"https://www.instagram.com/p/게시물코드/"` (앱에서 ··· → 링크 복사)
- **사진 파일을 저장소에 올리지 않습니다.** 주소만 적으면 사이트가 원래 게시물을 그대로 띄웁니다.
- 공식 계정(@sa2m2nam3, @sa2m2nam3_JP, 위버스 공식) 게시물만 넣습니다. 팬 계정 게시물은 넣지 않습니다.

### 3-3. 압축본의 멤버·기념일 고치기 → `data/episodes/파일`

새 압축본은 자동으로 추가되지만, 멤버는 제목·해시태그에 나온 이름으로만 채워집니다. 빠졌으면 직접 고칩니다.

1. `data/episodes` 폴더에서 해당 편을 찾습니다. 파일 이름은 `라이브날짜_...json` 입니다.
2. 연필 아이콘으로 열고 아래 줄을 고칩니다.

```json
  "members": ["soha", "mei", "hitomi", "junhwi"],
  "anniversary": "메이 생일",
```

- 기념일 편이 아니면 `"anniversary": null` 그대로 둡니다.

### 3-4. 장면(챕터) 시간 넣기 → 유튜브 설명란 (파일 수정 필요 없음)

유튜브 스튜디오에서 영상 **설명란**에 아래처럼 적으면, 1시간 안에 사이트 장면 목록이 자동으로 채워집니다.

```
0:00 인사
1:25 팬콘 오시나요?
12:03 5시간 연습하고 왔어요
```

- 첫 줄은 꼭 `0:00` 으로 시작, 장면은 3개 이상.
- 이미 장면 시간이 채워진 편은 다시 바꾸지 않습니다. 고치려면 그 편 파일의 `chapters` 를 직접 고칩니다.

### 3-5. 쇼츠를 본편에 붙이기 → 유튜브 쇼츠 설명란 (파일 수정 필요 없음)

쇼츠 설명란에 본편 링크(`https://youtu.be/본편id` 또는 영상 링크)를 넣으면 1시간 안에 자동으로 해당 편에 붙습니다.

### 3-6. 압축본이 사이트에 안 나올 때

- 유튜브에서 **공개**(또는 일부 공개)인지 확인합니다. 비공개·예약 상태면 사이트에 안 나오는 게 정상입니다.
- 압축본은 채널 **동영상** 탭에 있는 영상만 자동으로 들어옵니다(쇼츠 제외).
- 공개로 바꾼 뒤 최대 1시간 기다립니다. 바로 반영하고 싶으면 5번의 "지금 바로 다시 올리기"를 합니다.

### 3-7. 새 앨범·곡 → `data/discography.json`

```json
  {
    "id": "new-single",
    "title": "앨범 이름",
    "type": "싱글",
    "releaseDate": "2026-12-01",
    "titleTrack": "타이틀곡 이름",
    "mv": "https://www.youtube.com/watch?v=뮤직비디오id",
    "source": "https://기사나 공식 공지 주소"
  }
```

- 발표만 되고 날짜가 없으면 `"releaseDate": null`, `"status": "발매 예정 · 일자 미정"` 을 넣습니다.
- 뮤직비디오가 아직 없으면 `"mv": null`.

### 3-8. 삭제·정정 요청이 왔을 때

1. 해당 내용이 들어 있는 파일(일정이면 `events.json`, 사진이면 `photos.json` 등)을 엽니다.
2. 그 항목을 `{` 부터 `}` 까지 지우고, 앞뒤 쉼표가 맞는지 확인합니다.
3. Commit changes. 1~3분 뒤 사이트에서 사라집니다.
4. 압축본 영상 자체를 내려야 하면 유튜브에서 비공개로 바꾸면 1시간 안에 사이트에서도 사라집니다.
   - 즉시 내리려면 5번의 "지금 바로 다시 올리기"를 합니다.

### 3-9. "같은 날로 보이는 라이브" 확인·제외하기 → `data/sameday-review.json`

사진 페이지와 압축본 페이지의 "같은 날로 보이는 …"은 매시간 자동으로 추정합니다(`scripts/sameday.mjs`).
- 공식 사진과 라이브 영상 장면의 옷·머리·장소, 옷 색을 비교합니다.
- 사진이 올라온 날 **하루 전부터 7일 뒤까지**의 라이브만 비교합니다. 같은 옷을 몇 주 뒤 다시 입어도 엮이지 않습니다.
- 같은 옷이 서로 다른 날짜 라이브에 모두 보이면 날짜를 정하지 않고 "같은 옷이 여러 날 라이브에 보입니다"로 표시합니다.
- 기준이 엄격해서 놓치는 경우가 있습니다(시험: 같은 날 쇼츠 19개 중 8개 찾음, 다른 날 90쌍 중 잘못 0개).

자동 결과는 `data/sameday.json`에 쌓입니다(직접 고치지 마세요). 기준에 못 미친 후보는 `"level": "check"`로 들어 있고 사이트에는 안 보입니다.

**맞다/아니다를 직접 정하려면** `data/sameday-review.json`에 적습니다. 자동 결과보다 이 파일이 우선합니다.

```json
[
  {
    "photo": "https://x.com/sa2m2nam3/status/게시물번호",
    "episode": "250808_085XLbwZO7g",
    "status": "confirmed"
  }
]
```

- `photo`: `data/photos.json`에 있는 게시물 주소 그대로
- `episode`: 압축본 파일 이름에서 `.json`을 뺀 것(`data/episodes/` 안)
- `status`: 같은 날이 맞으면 `"confirmed"`(확인됨으로 표시), 아니면 `"rejected"`(다시는 안 보임)
- 자동 결과에 없는 짝도 `"confirmed"`로 적으면 표시됩니다.

## 5. 반영됐는지 확인하는 법 / 지금 바로 다시 올리기

1. 저장소 위쪽 **Actions** 탭을 누릅니다.
2. 맨 위 "GitHub Pages에 올리기" 줄을 봅니다.
   - 초록 체크 ✅: 반영 완료.
   - 노란 점 🟡: 진행 중 (1~3분).
   - 빨간 X ❌: 실패. 눌러서 빨간 단계를 열면 원인이 나옵니다. 대부분은 쉼표·따옴표 실수라서 방금 고친 파일을 다시 열어 확인하면 됩니다. 실패해도 사이트는 이전 상태로 열려 있습니다.
3. **지금 바로 다시 올리기**: Actions 탭 → 왼쪽 "GitHub Pages에 올리기" → 오른쪽 **Run workflow** → 초록 **Run workflow**.
   - 유튜브 확인도 같이 실행됩니다.

자동 실행 기록에 `github-actions[bot]` 이름으로 "유튜브 새 영상 반영" 커밋이 생기는 건 정상입니다.

## 6. 사이트가 안 열릴 때

- Settings → Pages → Build and deployment → **Source** 가 **GitHub Actions** 인지 확인합니다.
- 저장소가 **Public(공개)** 인지 확인합니다(무료 GitHub Pages 조건).
- Actions 탭에서 최근 실행이 빨간 X인지 확인합니다(5번).

## 7. Claude 예약 작업(크레딧 드는 것) 끄기·바꾸기

매일 저녁 7시 37분에 공식 X·기사에서 일정·사진을 찾는 Claude 예약 작업이 있습니다(이름: **세마넴 일정·사진 매일 찾기**). 이것만 크레딧이 듭니다.

- 꺼도 사이트와 유튜브 자동 갱신(GitHub Actions)은 그대로 무료로 돌아갑니다.
- 끈 뒤에는 일정·사진을 3-1, 3-2 방법으로 직접 넣으면 됩니다.

## 8. 유튜브 자동 갱신이 멈췄을 때

- Actions 실행 기록의 "유튜브 새 영상 확인" 단계에 `유튜브 확인 실패` 가 계속 보이면 유튜브 페이지 구조가 바뀐 것일 수 있습니다.
- 이때도 사이트 배포는 계속됩니다. 새 편은 `data/episodes/` 에 파일을 직접 만들어 넣으면 됩니다. 칸 설명과 예시는 [data/README.md](../data/README.md) 에 있습니다. 기존 파일 하나를 복사해서 값만 바꾸는 게 가장 쉽습니다.
- 자동 갱신 코드: `scripts/sync-youtube.mjs` (채널 핸들 `smn00000` 이 바뀌면 파일 위쪽 `HANDLE` 값을 고칩니다).
